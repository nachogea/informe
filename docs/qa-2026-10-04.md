## Recommendation

Ship a focused public **experimental native viewer for agent-generated reports,
dashboards and plans**. Its promise is: ask an agent for a document, open it
reliably, read it comfortably, copy useful content, and see valid updates.

The implementation has a credible core. It is not yet a polished downloadable
Mac product. The shortest path is to reduce modes and fix ordinary interactions.
Public source availability does not need to wait for PDF, integrations, new chart
types, collaboration, or another performance comparison. Signed installation is
a separate gate for a dependable end-user download.

## Confirmed issues to fix

### 1. Mixed numeric/text sorting is inconsistent

`src/data_visuals.rs:259` chooses numeric comparison when both cells parse as
numbers and lexical comparison otherwise. This creates a comparison cycle:

```text
2 < 10       numeric
10 < 1a      lexical
1a < 2       lexical
```

A standalone reproduction compiled the exact current `sorted_rows` function.
Sorting each rotation of `["2", "10", "1a"]` ascending retained a different
order. The existing test only covers entirely numeric currency values.

Fix with one consistent column policy (numeric when all applicable cells qualify,
otherwise text), or a documented total order across cell categories. Include blanks,
mixed values, equal values and ascending/descending cases. Keep useful sorting;
cut the attempt to infer numeric ordering independently for every pair.

### 2. Plan completion state disappears in copy/export

`src/artifact.rs:415` ignores the Markdown list item's checked state. The exact
current plain-text function produces:

```text
Input:                 Whole-document copy / PNG text:
- [x] Completed        • Completed
- [ ] Pending          • Pending
```

The exported plan fixture visibly loses the difference between completed work
and pending work. Preserve `[x]` and `[ ]` in semantic text output. This affects
whole-document copy and PNG; it is not a claim about dragging a rendered checkbox.

### 3. Table titles are absent from search and document text

`ArtifactNode::text_content` at `src/artifact.rs:272` includes table headers and
cells but omits the title. `ViewerUi::rebuild` uses that content for its leaf search
index. Consequently, searching the sample dashboard for “Prioritized savings
opportunities” cannot find the visible table title; whole-document copy also
omits it. Include the title in document/search text while keeping rectangular
TSV/CSV export in `table_data` separate.

### 4. Export promises exceed the current output

The PNG painter is a separate layout implementation. Native dashboard chart values
such as `$188,000` export as `188000 USD`; native Markdown tables become loose text
lines, and bold text, code styling and links lose their visual treatment. The
report image's “How we evaluate it” table is especially hard to scan. These are
documented limits, but a prominent Save PNG button makes them ordinary product UX.

Move PNG out of the primary toolbar. Treat its current implementation as an
optional/experimental export, and fix content loss even if formatting stays limited.
Do not turn a flattened PNG into the proposed searchable PDF feature.

### 5. Native accessibility and keyboard affordances need a release pass

The inspected accessibility tree exposed the window, traffic-light controls,
title and application menu, but none of the visible document text, toolbar actions,
tabs, table controls or headings. The app menu only declares Quit
(`src/main.rs:174`), and custom toolbar controls are clickable divs. This is evidence
of an accessibility gap, not a completed VoiceOver audit.

Verify accessible names/roles, document reading, keyboard focus and menu commands.
Add normal File/Edit/View affordances and shortcuts for the core actions before
describing the app as polished. Do not treat cutting features as a substitute for
accessible reading and copying.

### 6. First-run and docs still describe several different products

- Default launch and the bundle resource use the original AWS demo with an
  enabled-looking “Inspect unused shards” button. Its only action is `noop`.
- A document title appears in the titlebar, tab, toolbar and document heading.
- The README advertises sorting near the top but says tables “have no sorting”
  in Current limits (`README.md:204`).
- The README prominently compares the earlier runtime against fresh Chromium;
  current viewer timings and the important caveats appear elsewhere.
- Setup currently teaches a shell-local PATH export. The personal symlink installed
  on this development machine is not a reproducible public installation flow.
- The app bundle has no document type registration, and the application does not
  implement Finder open-file routing. Either implement that workflow or clearly
  scope the first preview to CLI/agent launch and the in-app file picker.

Use a small welcome/recent-documents view on ordinary launch, with an explicitly
illustrative sample. Show the document title in its tab and body; remove the
redundant toolbar copy. Align setup, README, agent skill and packaged examples with
the actual supported workflow.

## Proposed cuts and what survives

| Surface | Recommendation for the first public viewer | What to preserve |
| --- | --- | --- |
| Review/comments, diff outlines, revision submission | Remove from the default product UI, onboarding and primary skill path; retain as an explicitly experimental workflow if needed | Stable IDs, metadata and existing sidecars; do not delete user feedback |
| Developer inspector | Development-only, outside the ordinary More menu | Schema/capabilities/validation CLI for agents and contributors |
| Global Select components mode | Remove from ordinary reading; offer Copy table / Export CSV directly on each table | Normal text selection, whole-document copy and table data export |
| No-op artifact buttons | Stop authoring/advertising them; render legacy ones visibly disabled or deprecated | Backward-readable documents; no new action system |
| Save PNG in the toolbar | Remove primary placement; keep an optional overflow or CLI export while its limitations are explicit | Existing implementation can remain until export priorities are settled |
| Extra chrome | Remove duplicated toolbar title and routine reload/debug controls; keep one quiet reading toolbar | Tabs, Open, Find, Contents and clear error recovery |
| Metadata/source panel | Consolidate as optional document information rather than another interaction mode | Honest source metadata and usable links |
| Zed/Herdr integration work | Defer until the standalone viewer earns use | Existing CLI and installed generation skill |
| Benchmarks as the product pitch | Keep the research under benchmarks; remove historical speed/token comparisons from the main sales argument | Raw results, limitations and the queued matched-generation experiment |
| PDF and more visual primitives | Do not make them gates for publishing an experimental source repo | PDF can become the next focused sharing feature after viewer polish |

The three dedicated review files alone contain about 1,400 of the project's 5,476
Rust lines, including tests, with further hooks in rendering and the workspace.
That is a meaningful maintenance commitment for a workflow the current product
direction does not prioritize. This supports removing its default surface, not
deleting tested code or stored feedback without a migration decision.

Keep Markdown for prose and semantic JSON for dashboards, stable IDs, one theme,
metrics/callouts/bar charts/tables, one running app, tabs/recent documents,
validation, automatic reload and last-valid-content recovery. These are the
coherent core. Avoid changing the framework or designing another abstraction layer.

## Small implementation sequence

1. Fix mixed sorting, task-state preservation, table-title search/copy and stale docs.
2. Remove review/inspector/component-mode exposure from ordinary reading; add direct
   table actions, demote PNG, remove dummy buttons from examples and simplify chrome.
3. Run the manual reading/keyboard/accessibility pass below. Fix defects before
   expanding the component set. Add modest input/resource limits and measure larger
   documents before claiming large-document support: every open tab currently reads
   its full source every 250 ms and rendering is not virtualized.
4. Make the README and setup reproducible for a source preview, provide the three
   working examples, and publish with explicit experimental/platform limitations.
   Signing/notarization and clean-Mac verification gate downloadable-app claims.

## Manual acceptance script

Run from a directory outside this checkout with the locally installed launcher.
Use copies of fixtures for edits; keep the original examples intact.

```sh
artifact-preview open ~/code/artifact-preview/examples/viewer/dashboard.json
artifact-preview open ~/code/artifact-preview/examples/viewer/report.md
artifact-preview open ~/code/artifact-preview/examples/viewer/plan.md
```

- [ ] The requested document becomes visible; reopening it reuses its tab.
- [ ] Each document reads comfortably at narrow, default and wide sizes.
- [ ] Drag-select a sentence, copy it and paste into another app; double-click a
  word and repeat. Select All includes offscreen content and preserves task state.
- [ ] Find a visible table title and repeated prose; check Enter, Shift-Enter,
  Escape and that the displayed match count describes what is navigated.
- [ ] Contents and internal links reach the expected section; normal external
  links open deliberately. Tab changes and closing tabs preserve useful focus.
- [ ] Sort numbers, text, mixed cells and blanks in both directions. Copy/export
  table data and verify whether its ordering matches the stated export behavior.
- [ ] Update a temporary copy, break its JSON, then repair it; check readable error
  messaging, preserved content, cleared error and a stable reading position.
- [ ] Tab through core controls and use VoiceOver to inspect names/roles and read
  content. Test keyboard commands from document, Find and menu focus.
- [ ] Check the chosen export in another app, including the last section, Unicode,
  task state and tables; canceling a save dialog must leave the viewer usable.

This checklist remains open until a fresh manual pass is recorded. Public repo
visibility, signing and external publication were not changed by this assessment.
